# UX Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the 2026-10-31 UX review: consistent env names/badges/dates, one table pattern, less noise, a few missing affordances.

**Architecture:** Mostly client-side changes in shared components (`components/ui/data-table.tsx`, `components/app-sidebar.tsx`, `components/issues-board.tsx`) so each fix lands once and every page inherits it. One hand-written migration adds `environments.host`, backfills short names and rewrites status-less saved views. Pure helpers in `lib/` carry the logic that gets unit tests.

**Tech Stack:** Bun, Hono, Vite, TanStack Router/Query/Table v9, shadcn on `@base-ui/react`, use-intl, date-fns, Drizzle (Postgres 18), vitest, Playwright, Biome.

**Spec:** `docs/superpowers/specs/2026-10-31-ux-polish-design.md`

## Global Constraints

- No new runtime dependency; no visual re-theme.
- Every new/changed UI string in all five `messages/{ar,en,es,id,zh}.json`; `tests/motif-messages.test.ts`-style parity must hold.
- All identifiers, comments, commit messages in English. No `Co-Authored-By: Claude` in commits.
- Environment slugs never change.
- Topbar clock (`components/server-time.tsx`) is not touched.
- Env Issues page keeps listing the whole project; subtitle stays.
- Migration: `drizzle/20261031000000_env_host/migration.sql`, `BEGIN…COMMIT`, header comment citing the spec, additive, safe before deploy.
- Live DB apply (Task 16) only after a fresh backup, a dry run, and the user's explicit go-ahead in that moment.
- Gate per task: `bun run typecheck && bun run lint && bun run test` green; Playwright (`bun run test:e2e`) at the end of each phase.

## Review Focus

1. Env name that is only a parenthesised host, e.g. `(56.117)` → backfill must leave the name untouched (never empty). Test in Task 1 dry run.
2. Two envs that collapse to the same short name in one project (`Dev (56.117)` and `Dev (56.118)`) → second one skipped with a NOTICE, no unique-violation abort. Task 1.
3. A user who bookmarked `/issues?status=open` → still exactly the `open` status, not "active". Task 5 test.
4. Restore-only role on Databases → sees backup list with Restore, no Run backup, server returns the list. Task 13 test.
5. Table with exactly one page of rows → no pager and no empty white box; with 200 rows → bounded height with sticky header still scrolls. Task 6 Playwright check.

**Files:**
- Create: `drizzle/20261031000000_env_host/migration.sql`
- Modify: `lib/db/schema.ts:137-166` (add `host: text("host")` after `owner`)

**Interfaces:**
- Produces: `environments.host: string | null` column; Drizzle type `Environment["host"]`.

- [ ] **Step 1:** Add the column to the schema with a comment ("free-text address shown next to the short name; not used to connect").
- [ ] **Step 2:** Write the migration. Order inside one transaction:
  1. `ALTER TABLE environments ADD COLUMN IF NOT EXISTS host text;`
  2. A `DO $$ … $$` block looping over `environments e JOIN projects p` computing, in plpgsql:
     - `host := substring(e.name from '\(([^()]*)\)\s*$')`; `base := regexp_replace(e.name, '\s*\([^()]*\)\s*$', '')` when host is not null, else `e.name`.
     - if `lower(base)` starts with `lower(p.name) || ' '`, strip that prefix (match `stripProjectPrefix` in `lib/nav-path.ts:97`, separators `[\s:–—-]+`).
     - `base := btrim(base)`; skip when `base = ''` or `base = e.name and host is null`.
     - skip with `RAISE NOTICE 'skip % (%): collides with existing name %'` when another env in `p.id` already has `name = base` (check against current table state, so earlier updates in the loop count).
     - otherwise `UPDATE … SET name = base, host = coalesce(e.host, host)` and `RAISE NOTICE 'env % : % -> % | host %', e.id, e.name, base, host`.
  3. `UPDATE saved_views SET params = params || '{"status":"all"}'::jsonb WHERE NOT params ? 'status';`
- [ ] **Step 3: Dry run on local DB.** Start `docker compose up -d postgres`, `bun run db:migrate` to latest, insert fixtures covering: `Sucor Membership Dev 1 (56.129/membership.sucor-int.id)`, `(56.117)`, `Dev (56.117)` + `Dev (56.118)` in one project, a name without parens. Run the file with `COMMIT` replaced by `ROLLBACK` via `psql -v ON_ERROR_STOP=1`. Expected NOTICEs: rename to `Dev 1` / host `56.129/membership.sucor-int.id`; `(56.117)` untouched; second `Dev` skipped; no errors. Then run for real locally.
- [ ] **Step 4:** `bun run typecheck` passes.
- [ ] **Step 5: Commit** `feat(db): add environment host and backfill short names`
