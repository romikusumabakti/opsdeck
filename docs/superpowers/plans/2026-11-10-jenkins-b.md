# Retire Jenkins, part B: legacy artifact deploys — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Panel deploys legacy jar and static (`dist`) artifacts built by Woodpecker to non-Docker Rocky 8 VMs, replacing the Jenkins `SERVER_*` jobs.

**Architecture:**
- Deploy targets get a `kind`: `compose` (today), `jar`, or `static`.
- Generated pipelines gain an `artifact` build:
  - the toolchain runs as a check step;
  - the build step packs the artifact into the existing `${componentKey}-deploy:${TAG}` scratch image under `/bundle/artifact/`.
- For non-compose kinds, the deploy job:
  1. reads that image's single layer from the registry;
  2. streams it over SSH into a staging dir;
  3. runs a jar or static swap script with a health check.
- Choosing a target branch commits the generated pipeline to that branch.

**Tech Stack:** Bun, Hono, React 19 + TanStack, shadcn/ui (Base UI), Drizzle/Postgres, BullMQ, ssh2/node-ssh, Vitest, Biome.

**Spec:** `docs/superpowers/specs/2026-11-10-jenkins-b-legacy-artifacts-design.md`. Recon: `docs/superpowers/specs/recon-2026-11-10-project-4b.md` (untracked scratch).

## Global Constraints

- **Migrations:**
  - Each is a folder `drizzle/<YYYYMMDDHHMMSS>_<name>/migration.sql` plus `snapshot.json`, generated with drizzle-kit and then hand-checked.
  - The first line is `SET LOCAL lock_timeout = '5s';--> statement-breakpoint`. No BEGIN/COMMIT.
  - Changes are additive. New enum values use `ADD VALUE IF NOT EXISTS`.
  - Each migration gets a static test like `tests/migrations-environment-teardown.test.ts`.
- **Language:** everything developer-facing is in English. End-user text goes in the i18n catalogs `messages/en.json` and `messages/id.json`.
- **Tests:**
  - Full suite: `bun run test > /tmp/suite.log 2>&1`. Before any commit, `grep -cE "FAIL|×" /tmp/suite.log` must print `0`.
  - Lint: `bunx biome check <files>`. Types: `bunx tsc --noEmit -p .`
- **Image pushes:** every pushed image uses `docker buildx build --provenance=false --output type=registry,oci-mediatypes=false` (`PUSH_FLAGS` in `lib/ci/pipeline.ts`).
- **Tags:** `origin-<branch with / → ->-<sha>`. The scheme is unchanged.
- **Secrets:** never in logs, errors or run output. Use the `secrets` redaction of `executeRemoteCommand`.
- **Scripts shipped to servers:** POSIX `sh`, `set -eu`, every interpolated value quoted with `shq` from `lib/sh.ts`.
- **Artifact layout:** inside the deploy image, the artifact lives under `/bundle/artifact/`:
  - jar kind: exactly one `*.jar` file;
  - static kind: the contents of `dist/`, including `index.html`.
- **Rename on deploy:** the jar is renamed to the target's `jarName`, e.g. `core-web-service.jar`.
- **Previous copies:**
  - jar: `<deployDir>/.opsdeck-prev/<jarName>`;
  - static: `<webRoot>.opsdeck-prev` (sibling dir).
- **Staging:**
  - jar: `<deployDir>/.opsdeck-incoming`;
  - static: `<webRoot>.opsdeck-incoming`.
- **Jar health:** the unit is `active` and its `MainPID` is unchanged for 30 s (`stableSeconds`). If `healthUrl` is set, `curl -s -o /dev/null -w '%{http_code}'` must give a status below 500, with the overall deadline `healthTimeoutSeconds`.
- **Health failure:** no automatic revert.

## Review Focus

1. **First deploy to a static web root that does not exist yet.** Expected: it is created; no `chown`/`chcon` reference copy (nothing to copy from); nginx is reloaded. Owner: Task 7.
2. **A jar target whose systemd unit does not exist or fails to stop.** Expected: the script fails before touching the current jar. The jar on disk is unchanged. Owner: Task 7.
3. **A registry manifest that is an index (multi-platform), OCI-typed, or has more than one layer.** Expected: the deploy fails with a clear "artifact image must be a single-layer Docker image" message, and nothing reaches the server. Owner: Task 5.
4. **Two static targets on one host deploying at once.** Example: .122 core frontend and portal frontend, from two environments. Expected: their nginx `-t`/reload sections never interleave; a host-level `flock /run/opsdeck-nginx.lock` around test+reload. Owner: Task 7.
5. **Changing a target's branch to one whose pipeline commit fails** (forge error, or a foreign `.woodpecker.yaml`). Expected: the target update still saves. The response lists the pipeline-file failure, as `ensureComponentBranch` does today. `deployNextBuild` is set. Owner: Task 9.

### Task 7: The jar and static deploy scripts

**Files:**
- Create: `lib/deploy/artifact-script.ts`
- Test: `tests/artifact-deploy-script.test.ts`. Execute the generated script under `sh` with stub `systemctl`, `nginx`, `curl`, `chcon` and `selinuxenabled` on `PATH`, like `tests/deploy-script.test.ts`.

**Interfaces:**
- Produces:
  - `artifactStagingDir(kind: "jar" | "static", deployDir: string): string` → `<deployDir>/.opsdeck-incoming` or `<deployDir>.opsdeck-incoming`.
  - `buildArtifactExtractCommand(stagingDir: string): string`. Its effect: `rm -rf <staging> && mkdir -p <staging> && tar -xzf - -C <staging> bundle/artifact`.
  - `buildArtifactDeployScript(input: { kind: "jar"; deployDir: string; jarName: string; systemdUnit: string; healthUrl: string | null; healthTimeoutSeconds: number; stableSeconds?: number } | { kind: "static"; deployDir: string; healthTimeoutSeconds: number }): string`.
    - It validates the input with the Task 2 schemas.
    - Its output markers mirror the compose script: `HEALTHY`, `HEALTH TIMEOUT`, `DEPLOY LOCKED`.
- **Script behaviour (normative):**
  - **Common:**
    - `set -eu`, `trap '' HUP PIPE`;
    - `flock -w 600 9` on `<deployDir>/.opsdeck-deploy.lock` for jar, and on `<deployDir>.opsdeck-deploy.lock` for static;
    - `trap` removes the staging dir on exit.
  - **jar:**
    1. Exactly one `*.jar` must be in `<staging>/bundle/artifact/`, and non-empty. Otherwise `ARTIFACT INVALID` and exit 1.
    2. `systemctl cat <unit>` must succeed, else `UNIT NOT FOUND` and exit 1.
    3. If `systemctl is-enabled <unit>` is not `enabled`, run `systemctl enable <unit>` and print `Enabled <unit>`.
    4. `systemctl stop <unit>`.
    5. `mkdir -p .opsdeck-prev`; move the current `<jarName>` there if present; move the staged jar to `<deployDir>/<jarName>`.
    6. `systemctl start <unit>`.
    7. Health loop until the deadline:
       - each poll reads `ActiveState`, `MainPID`, and the URL status if set;
       - OK means `active`, PID > 0, and status < 500 when a URL is set;
       - `HEALTHY` after consecutive OK polls with the same PID spanning `stableSeconds`;
       - otherwise `HEALTH TIMEOUT` and exit 1.
  - **static:**
    1. `<staging>/bundle/artifact/index.html` must exist, else `ARTIFACT INVALID`.
    2. If `<webRoot>` exists, copy owner and mode with `chown -R --reference` and `chmod -R --reference`, and run `chcon -R --reference` when `selinuxenabled` succeeds.
    3. Move the staged artifact to `<webRoot>.opsdeck-new`.
    4. Inside `flock -w 120 8` on `/run/opsdeck-nginx.lock`:
       - `rm -rf <webRoot>.opsdeck-prev`;
       - move the current root to `.opsdeck-prev` if it exists;
       - move `.opsdeck-new` to `<webRoot>`;
       - `nginx -t`. If that fails, undo (restore prev, remove the new tree), print `NGINX CONFIG INVALID`, exit 1;
       - `systemctl reload nginx`.
    5. Print `HEALTHY`.

  - jar with an unknown unit: `UNIT NOT FOUND`, the current jar is unchanged (Review Focus 2);
  - jar with the unit disabled: `Enabled core` is printed;
  - jar whose PID changes between polls (crash loop): `HEALTH TIMEOUT` (use `stableSeconds: 2`, timeout 5);
  - jar with the URL answering 503: `HEALTH TIMEOUT`;
  - jar with two jars staged: `ARTIFACT INVALID`;
  - static happy path: prev kept, reload called;
  - static first deploy with no web root: no chown/chcon, root created, reload (Review Focus 1);
  - static with `nginx -t` failing: the old root is restored, `NGINX CONFIG INVALID`;
  - static uses the `/run/opsdeck-nginx.lock` flock (assert the stub flock sees the path) (Review Focus 4);
  - deploy dir with a space or a `'`: quoted correctly.
